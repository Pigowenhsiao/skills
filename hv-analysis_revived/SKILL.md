# 橫縱分析法深度研究

> **方法論源流**
> 橫縱分析法由數位生命卡茲克（Khazix）提出，融合語言學中的歷時與共時分析（Saussure）、社會科學中的縱向與橫斷面研究設計、商學院個案研究法，以及競爭策略分析的核心思想，形成一套適用於產品、公司、概念與人物研究的通用框架。核心原則不變：縱向追時間深度，橫向追同期廣度，最後在交會處產生判斷。

你正在執行一次橫縱分析法深度研究。最終產出是一份**排版精美的 PDF 研究報告**。

## 前置準備

### 環境準備

1. **確認 PDF 轉換腳本可用**：本 Skill 內建 `scripts/md_to_pdf.py`（基於 WeasyPrint），用來把最終 Markdown 報告轉成排版精美的 PDF。請確認依賴已安裝：`pip install weasyprint markdown --break-system-packages`。
2. **寫作風格**：本 Skill 已內建完整的寫作風格指南（見下方「寫作風格」段落），不需要額外載入其他 Skill。

### 明確研究對象

拿到使用者輸入後，確認以下資訊。如果使用者已經講得夠明確（例如「幫我用橫縱分析法研究 Hermes Agent」），就不要再追問，直接開始：

1. **研究對象**：具體的產品名、公司名、概念名或人物名
2. **類型**：產品、公司、概念、人物，或其他
3. **研究動機**（可選）：為什麼要研究它？最近發生了什麼事？
4. **特別關注點**（可選）：有沒有特別想深入的方向？

## 第一步：連網資料蒐集

這套方法論的品質，完全取決於資料的豐富度與準確性。**必須連網查找**，不能只靠既有知識。研究報告的價值在於深度與完整性，所以資料蒐集階段寧可多查，也不要因為資料不足，讓後面的分析停留在表面。

### 平行蒐集策略

優先使用目前執行環境中可用的連網工具來平行蒐集資料。如果當前環境支援多代理或平行分工，可以照下面方式拆任務；如果不支援，就由目前代理依照相同分工順序串行完成，標準不變。

- **縱向資料流**：研究對象的起源、創辦人背景、發展歷程、關鍵事件、版本迭代、募資、策略轉向、危機
- **橫向資料流**：競品辨識、各競品的特點與使用者口碑、產業對照評測、市場版圖
- **補充資料流**（複雜對象才需要）：創辦人深度背景、產業環境變化、使用者社群討論（GitHub Issues、Reddit、Twitter/X、知乎等）

### 連網蒐集指引

連網時請遵守以下原則：

> 你需要連網取得資料。優先使用當前環境已提供的網頁搜尋、頁面擷取、瀏覽器或 fetch 工具；不要預設某個固定工具名稱、固定 Skill 路徑，或某個特定 Agent 平台一定存在。
> - 搜尋策略：先用搜尋工具找線索與來源，再用頁面擷取或瀏覽工具深入讀取
> - 多次搜尋、組合多組關鍵字，不要只查一次就放棄
> - 一手來源優先於二手來源：官方部落格 > 權威媒體原創報導 > 轉載或聚合
> - **學術型研究對象一定要查 arXiv**：如果研究對象涉及學術概念、演算法、AI 模型、技術典範等，必須透過 arXiv API 取得相關論文。呼叫方式：`curl -s "https://export.arxiv.org/api/query?search_query=all:關鍵字1+AND+all:關鍵字2&max_results=10"`，或使用當前環境可用的 fetch / web 工具存取同一個 URL。回傳為 XML 格式，包含標題、作者、摘要、發布日期與 PDF 連結。可依需要調整關鍵字組合與結果數量。找到關鍵論文後，再讀取論文摘要頁（`https://arxiv.org/abs/論文ID`）取得更多細節。

給執行者的指令要描述目標（例如「取得」、「調研」、「了解」），不要把流程寫死成某個固定工具調用，讓執行者根據當前環境選擇最合適的方式。

### 資料來源優先順序

一手來源優先於二手來源。多個媒體引用同一個錯誤資訊，會造成循環印證的假象：

| 資料類型 | 優先來源 |
|---------|---------|
| 產品更新 / 技術決策 | 官方部落格、GitHub Release Notes、創辦人貼文 |
| 募資 / 商業資料 | 公司官方公告、SEC / 工商文件 |
| 使用者口碑 | GitHub Issues、Reddit 討論、Twitter/X、知乎貼文 |
| 產業分析 | 權威媒體原創報導（非轉載） |
| 學術 / 技術原理 | arXiv 論文（`export.arxiv.org/api/query`）、Google Scholar、學術會議論文集 |

### 資料充分性自我檢查

搜尋完成後檢查：

- 縱向：能講出一個完整的故事嗎？有沒有明顯的資料斷層？
- 橫向：競品清單完整嗎？有沒有漏掉主要玩家？每個競品的資料夠不夠支撐對照？
- 來源：關鍵事實有可靠來源支撐嗎？有沒有只靠單一來源就下判斷？

資料不夠就再補查。不要勉強湊。

## 第二步：縱向分析（Diachronic / Longitudinal）

沿著時間軸，完整還原研究對象從誕生到現在的發展全貌。這是報告的主體，篇幅應該最重。

### 內容要求

**起源追溯**：它誕生的背景是什麼？基於什麼技術、理念或需求而來？創辦團隊或核心推動者是誰？這些人之前做過什麼，為什麼會是他們來做這件事？當時的產業環境是什麼樣子？有沒有某個關鍵事件或靈感，直接促成它的誕生？

**誕生節點**：明確交代首次發布、成立或提出的時間，最初的形態與定位，和現在有什麼不同。

**演進歷程**：從誕生到現在，依時間順序梳理所有關鍵節點。包括但不限於：重大版本更新、募資事件、團隊變動、策略轉型、技術架構變化、使用者規模里程碑、重大合作或收購、公關危機或爭議事件。

**決策邏輯**：在每個關鍵節點上，盡可能還原決策背後的原因。為什麼選 A 而不是 B？當時面對的限制條件是什麼？哪些早期決策「鎖住」了後續的發展方向，變得難以逆轉？是什麼機制讓它越走越深，例如網路效應、生態綁定、技術堆疊選擇等。

**階段劃分**：把整段歷程自然切成幾個階段，例如萌芽期、快速成長期、轉型期等，每個階段都要有明確的核心特徵與主要矛盾。

### 篇幅

6,000 到 15,000 字。歷史越長、節點越多的對象越接近上限，新生事物越接近下限。核心原則是把故事講完整、講透，每個關鍵節點都值得展開，不要為了壓縮篇幅而跳過重要細節。寧可寫長寫細，也不要蜻蜓點水。

## 第三步：橫向分析（Synchronic / Cross-sectional）

以當前時間點為切面，把研究對象和同賽道的競品或同類做全面對照。

### 先判斷競品情境

分三種情境處理：

**情境 A：沒有直接競品。** 如果研究對象是全新品類，或具備很強的獨占性，就跳過逐一對照，改成分析：它為什麼沒有競品？是品類太新、門檻太高，還是市場太小？未來最可能從哪個方向冒出競爭者？有沒有間接替代方案，或上一代解法可作為參照？

**情境 B：競品很少（1 到 2 個）。** 逐一深入對照，每個競品都展開詳細分析。

**情境 C：競品充足（3 個以上）。** 挑選最具代表性的 3 到 5 個進行對照，其餘簡要提及。

### 對照維度

根據研究對象的類型彈性調整，但至少要覆蓋以下面向：

**核心差異對照**：技術路線、核心方法論、底層邏輯、產品形態、商業模式、組織結構、目標使用者或受眾、使用情境、核心優勢與明顯短板、定價策略、資源投入、規模體量。

**使用者視角**：每個競品的真實使用者口碑如何？社群評價、使用體驗中最常被提到的優點與槽點是什麼？使用者實際怎麼用，和官方定位有沒有落差？對照不要寫成參數表的文字版，要講清楚每個競品「實際活成什麼樣子」，以及使用者選它的真實理由。

**生態位分析**：在整個賽道版圖中，研究對象位於哪裡？它填補了什麼空白，還是在跟誰正面競爭？目前格局是百花齊放、雙強對峙，還是一家獨大？

**趨勢判斷**：基於橫向對照，研究對象在競爭格局中的走向是什麼？機會與風險各在哪裡？

### 篇幅

3,000 到 10,000 字。情境 A 大約控制在 3,000 字左右；情境 C 中，每個主要競品至少要有 1,500 字以上的獨立分析，不要輕輕帶過。

## 第四步：橫縱交會洞察

這是整篇報告最精華的段落。把縱向發展脈絡與橫向競爭格局結合起來，提出綜合性的新判斷。不要寫成前面內容的縮寫版。

需要回答的核心問題：

1. **歷史如何塑造了當下的競爭位置**：縱向歷程中的哪些決策與事件，決定了它今天在橫向對照中的位置？
2. **競品的縱向對照**：如果把主要競品也放上時間軸看，它們的起源與演變路徑有什麼不同？這些差異如何導致今天各自的特徵？
3. **優勢的歷史根源**：今天的每一個核心優勢，可以追溯到歷史上的哪個節點或決策？
4. **劣勢的歷史根源**：今天的每一個核心劣勢，可以追溯到哪個歷史決策？當初的「好決策」有沒有變成今天的包袱？
5. **未來推演**：基於縱向趨勢與橫向競爭格局，提出三個劇本：最可能、最危險、最樂觀。每個劇本都要有清楚的邏輯支撐。

### 篇幅

1,500 到 3,000 字。

## 寫作風格

這不是一份冷冰冰的顧問式報告，而是一篇能讓人從頭讀到尾的深度研究。寫作風格要在「研究報告的嚴謹」與「卡茲克式可讀性」之間找到平衡。

### 從卡茲克文風借用的核心元素

以下風格元素要直接應用到報告寫作中（詳細定義可參考 `khazix-writer`）：

**節奏感**：句子有長有短，段落之間的推進自然。不要每段都一樣長；必要時可以用一句成段的方式製造重量。好的節奏像波動，每次圍繞主線稍微偏出去一點，再用一句「扣回主線」的句子拉回來。

**敘事驅動，不是條列驅動**：縱向部分要有故事弧線，有起承轉合。例如一個產品為什麼在某個時間點突然爆發，前面有哪些鋪陳，轉折在哪裡。不要寫成「2023 年 1 月發布 A，2023 年 3 月發布 B」的流水帳。

**知識要像聊天時自然拿出來**：在講述過程中順勢帶出背景知識，不要硬切成「下面我來科普一下」。

**敢下判斷**：可以提出觀點與洞察，但每個觀點都必須有事實支撐。先擺事實，再下判斷。若屬推測，要明確標示。表達判斷時，可以用「我的判斷是」這類承認主觀性的說法，而不是用居高臨下的定論語氣。

**層層剝開的修辭**：不要一上來就丟結論。改用「現象 → 表面解釋 → 更深一層的追問 → 核心洞察」的展開方式，讓讀者參與思考過程。

**文化升維**：在交會洞察段，連到更大的文化、哲學或歷史參照。不是硬湊，而是聊著聊著自然浮現的那種感覺。

**回環呼應**：開頭或縱向部分埋下的細節與鉤子，要在交會洞察或結尾 callback 回來。前後因果能閉合，報告才會從「資訊流」變成「作品」。

### 不要照搬的卡茲克文風元素

以下元素適合公眾號文章，不適合研究報告，要刻意節制：

- **過強的口語化**：報告可以有聊天感，但不要滿篇「這玩意」、「不是哥們」、「太猛了」。偶爾點綴可以，但密度要比文章低很多。
- **完全去小標題**：公眾號文章可以一口氣順下去不加小標題；研究報告不行。1 到 3 萬字的內容如果沒有清楚結構，讀者會迷路。
- **標點禁令可以放寬**：文章裡可能避免冒號與破折號，但研究報告要重視資訊傳達效率，可以正常使用。
- **固定尾段**：不要加文章式的三連、星標、導流結尾。

### 絕對禁區

以下 AI 味很重的表達，不管什麼文體都要避免：

- 套話：「首先……其次……最後」、「綜上所述」、「值得注意的是」、「不難發現」
- 空洞形容詞：「賦能」、「抓手」、「打造閉環」
- 教科書開頭：「在當今 AI 快速發展的時代」、「隨著技術不斷進步」
- 高頻踩雷詞：「說白了」、「意味著什麼」、「這意味著」、「本質上」、「換句話說」、「不可否認」
- 空泛工具名：不要寫「AI 工具」、「某個模型」，要寫具體名稱
- 編造場景：如果某項資訊查不到，就誠實標註「該資料暫缺」，絕不編造

### 用人話寫

避免顧問公司式的套話與空洞概括。用具體細節與例子代替抽象敘述。比如不要寫「該公司在這個階段實現快速成長」，而要寫「從 2024 年中期的 1,000 萬美元 ARR 到 2025 年底的 10 億美元，成長曲線幾乎是垂直的」。

## 第五步：產出 PDF 報告

報告寫完後，使用本 Skill 內建的 `scripts/md_to_pdf.py` 腳本，把 Markdown 轉成排版精美的 PDF。

### 轉換流程

1. **先完成 Markdown 稿件**：把完整報告寫成標準 Markdown，存成 `[研究對象]_橫縱分析報告.md`
2. **安裝依賴**（如尚未安裝）：`pip install weasyprint markdown --break-system-packages`
3. **執行轉換腳本**：
   ```bash
   python [skill目錄]/scripts/md_to_pdf.py input.md output.pdf --title "研究對象名稱" --author "Pigo"
   ```
4. 腳本會自動產生中介 HTML 檔（方便除錯）與最終 PDF

### 腳本內建排版規範

`md_to_pdf.py` 已內建完整的 CSS 排版方案，不需要手動調整：

- **頁面**：A4，頁邊距上 25mm、左右 20mm、下 20mm
- **封面頁**：自動產生，包含標題（28pt 深藍色）、副標題「橫縱分析法深度研究報告」、作者資訊、裝飾分隔線
- **配色**：H1 標題 = `#1a5276` 深藍、H2 = `#1e8449` 綠色、H3 = `#2e86c1` 淺藍、H4 = `#5b2c6f` 紫色，正文 = `#2c3e50` 深灰
- **字體**：CSS fallback 鏈 `"Droid Sans Fallback", Helvetica, Arial, sans-serif`，自動處理中英文混排
- **正文**：10.5pt，行距 1.75，左右對齊，含孤行 / 寡行控制
- **引用區塊**：左側 3pt 深藍豎線加淺灰背景
- **表格**：全寬、深藍表頭白字、斑馬紋列
- **頁眉**：「報告標題 | 橫縱分析法深度研究報告」（首頁不顯示）
- **頁腳**：「第 X 頁」（首頁不顯示）
- Markdown 的第一個 H1 會自動被抓成封面標題，正文中不會重複出現

### Markdown 寫作注意事項

為了讓腳本正確解析，並產出最佳 PDF 效果：

- 第一行用 `# 標題` 作為報告標題（會自動用於封面）
- 緊接標題後，可用 `> 研究時間：... | 所屬領域：... | 研究對象類型：...` 格式寫中繼資訊列，會被提取到封面
- 用 `##` 當主要章節標題（縱向分析、橫向分析、橫縱交會等）
- 用 `###` 與 `####` 當子章節
- 表格使用標準 Markdown 表格語法
- 引用使用 `>` 語法
- 粗體使用 `**文字**`

### 末尾內容

在 Markdown 稿件結尾加上：

- **資料來源**：所有引用來源清單，標註 URL 與存取時間
- **方法論說明**：簡要說明橫縱分析法的來源（1 到 2 句即可）

```text
封面頁

目錄

一、一句話定義
[用一句話說清楚這個東西是什麼]

[完整的縱向敘事，6,000-15,000 字]
```

## 不同研究對象類型的適配

核心原則不變（縱向追時間深度，橫向追同期廣度），但側重點不同：

**研究產品時**：縱軸重點放在版本迭代、技術路線演變、使用者成長曲線、關鍵產品決策；橫軸重點放在功能對照、效能對照、使用體驗、定價。

**研究公司時**：縱軸重點放在創辦團隊、募資歷程、策略轉向、組織變革、關鍵人事變動；橫軸重點放在商業模式差異、市占、營收對照、組織架構差異。

**研究概念時**（技術典範、商業模式、文化現象）：縱軸重點放在概念起源（誰提出、基於什麼理論或需求）、如何流行、經歷哪些爭論與演變；橫軸重點放在與相近概念的差異、各自適用情境、不同陣營的論證方式。

**研究人物時**：縱軸重點放在個人經歷、職涯軌跡、關鍵決策、成長曲線、公開言論變化；橫軸重點放在與同領域其他人物的對照，例如做事方式、風格、成就、影響力與路線選擇差異。

## 品質檢查清單

交付前自我檢查：

- [ ] 縱軸是敘事故事體嗎？讀起來有因果邏輯與時代脈絡？不是年表式流水帳？
- [ ] 創辦人 / 發起者的背景與動機有足夠深度嗎？
- [ ] 每個關鍵節點都有展開，沒有為了壓縮篇幅而跳過重要細節嗎？
- [ ] 決策邏輯有還原嗎？不只是「發生了什麼」，還有「為什麼這樣選」？
- [ ] 橫軸的競品情境判斷正確（A / B / C）嗎？競品分析夠深嗎？
- [ ] 使用者口碑部分有引用真實使用者的聲音嗎？不只是官方宣傳？
- [ ] 橫縱交會有產出新的判斷，不是前面內容的縮寫版嗎？
- [ ] 未來推演的三個劇本都有邏輯支撐嗎？
- [ ] 寫作風格有節奏感、有可讀性，不是冷冰冰的顧問式報告嗎？
- [ ] 沒有踩到上面列出的絕對禁區嗎？
- [ ] 所有關鍵事實都標明資料來源了嗎？
- [ ] 查不到的資訊有誠實標註「暫缺」，沒有編造嗎？
- [ ] PDF 排版美觀、結構清楚、可讀性高嗎？
- [ ] 總字數落在 10,000 到 30,000 字範圍內嗎？
