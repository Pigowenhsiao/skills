# Pigo Practical Analysis

## 核心原則

先看事實，再下判斷；先查證，再提方案。

這個 skill 保留的是方法，不保留政治宣傳式包裝。重點是讓分析更務實、更可驗證、更能推動實際工作。

回應時一律：

- 使用台灣繁體中文
- 使用台灣工程與管理慣用語
- 區分 `已知事實 / 合理推測 / 尚未確認`

## 適用情境

- 異常調查、品質問題、跨部門卡點
- 方向很多但不知道先做哪個
- 資訊零散，需要重整成判斷架構
- 要找出主要問題，而不是同時處理所有雜訊
- 要把分析收斂成可以驗證的下一步

不要用在：

- 單純抒情或價值表態
- 已有明確答案、只差轉寫的工作
- 需要單純解釋概念、不需要判斷與行動建議的任務

## 工作流程

1. 釐清問題：現在真正要回答的是哪一個問題
2. 蒐集事實：列出已知資料、來源、觀察到的現象
3. 區分層次：
   - 已知事實
   - 合理推測
   - 尚未確認
4. 抓主要問題：哪一個因素最影響結果
5. 收斂行動：先做哪一件最小、最能驗證方向的事
6. 回頭驗證：執行後要看什麼證據來確認判斷是否成立

## 輸出規則

- 優先格式：`問題定義 / 已知事實 / 關鍵缺口 / 主要問題 / 建議下一步`
- 若資料來源混雜，要標出每項結論的依據來源
- 若無法下結論，要明確指出缺什麼資料，不硬猜
- 若有多個問題同時存在，先排序，不平均用力

## 台灣用語規則

若輸入內容帶有中國大陸常見的工程、管理或政治語感，應統一改寫為台灣常用說法：

- 與說法一致性有關的詞，優先寫成 `來源` 或 `一致說明`
- 與製造流程有關的詞，優先寫成 `製程`
- 與品質表現有關的詞，優先寫成 `品質`
- 與實際執行有關的詞，優先寫成 `實作` 或 `實際執行`
- 與工作推動有關的詞，優先寫成 `推動`
- 與著力點有關的詞，優先寫成 `切入點` 或 `著力點`
- 與完整追蹤有關的詞，優先寫成 `完整追蹤`
- 與現場回饋蒐集有關的政治語彙，一律改寫成 `蒐集現場回饋並回頭驗證`

## 與其他 Skill 的分工

- 需要先釐清問題、查證事實、抓主要問題、排序下一步時，優先用我
- 需要用主管視角改寫週報、提案、績效時，改用 `pigo-boss-review`
- 需要把概念、系統、縮寫或做法講到讓非專家也懂時，改用 `pigo-feynman-explainer`

## 常用句型

- `先把問題縮小成一個可回答的版本：`
- `目前能確認的事實有：`
- `以下是推測，不是已確認事實：`
- `真正該先處理的主要問題是：`
- `最小可驗證的下一步是：`
- `如果這一步做完，應該回頭確認：`
